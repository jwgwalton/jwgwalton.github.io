MLOps Best Practices: From Notebook to Production

February 20, 2024 10 min read
MLOps Production Best Practices

The journey from a working Jupyter notebook to a production-ready ML system is often more challenging than training the model itself. This guide covers essential MLOps practices that will help you build reliable, scalable AI systems.

The MLOps Maturity Model

Before diving into specific practices, it's helpful to understand where your organization stands:

  • Level 0: Manual - Notebooks, manual deployments, no automation
  • Level 1: Automated Training - CI/CD for training, experiment tracking
  • Level 2: Automated Deployment - Automated model deployment and monitoring
  • Level 3: Full MLOps - End-to-end automation, A/B testing, auto-retraining

Version Everything

Code Versioning

This seems obvious, but ensure all your ML code is in version control: 

# .gitignore should exclude
data/
*.pkl
*.h5
models/
__pycache__/

Data Versioning

Use tools like DVC, Pachyderm, or Delta Lake to version your datasets: 

# Using DVC
dvc add data/training_data.csv
git add data/training_data.csv.dvc
git commit -m "Add training data v1"

Model Versioning

Track models with their metadata (hyperparameters, metrics, datasets): 

import mlflow

with mlflow.start_run():
    mlflow.log_params(params)
    mlflow.log_metrics(metrics)
    mlflow.sklearn.log_model(model, "model")

Experiment Tracking

Use tools like MLflow, Weights & Biases, or Neptune to track experiments:

  • Hyperparameters
  • Training metrics
  • Validation metrics
  • Model artifacts
  • Environment information

Reproducibility

Environment Management

Pin all dependencies and use containerization: 

# requirements.txt
numpy==1.24.3
scikit-learn==1.3.0
tensorflow==2.13.0

# Dockerfile
FROM python:3.10-slim
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . /app
WORKDIR /app

Random Seeds

Set seeds for reproducibility: 

import random
import numpy as np
import tensorflow as tf

def set_seeds(seed=42):
    random.seed(seed)
    np.random.seed(seed)
    tf.random.set_seed(seed)

CI/CD for ML

Continuous Integration

Automate testing for your ML code:

  • Unit tests for data preprocessing
  • Model performance tests
  • Data validation tests
  • API contract tests

Continuous Deployment

Automate model deployment with proper safeguards: 

# Example GitHub Actions workflow
name: ML Pipeline
on: [push]
jobs:
  train-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Train model
        run: python train.py
      - name: Validate model
        run: python validate.py
      - name: Deploy if passing
        if: success()
        run: python deploy.py

Model Monitoring

Once deployed, monitor your models for:

Performance Metrics

  • Prediction accuracy/error rates
  • Latency (p50, p95, p99)
  • Throughput
  • Resource utilization

Data Drift

Detect when input distributions change: 

from evidently import ColumnDriftMetric
from evidently.report import Report

report = Report(metrics=[
    ColumnDriftMetric(column_name='feature1')
])
report.run(reference_data=train_data, current_data=prod_data)

Model Drift

Monitor when model performance degrades over time.

Feature Stores

Centralize feature management with tools like Feast or Tecton:

  • Ensure training/serving consistency
  • Enable feature reuse across teams
  • Simplify feature versioning
  • Support real-time and batch features

Model Serving Strategies

Batch Prediction

For non-real-time use cases:

  • Run predictions on a schedule
  • Store results in database
  • Lower infrastructure costs

Online Serving

For real-time predictions: 

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class PredictionRequest(BaseModel):
    features: list[float]

@app.post("/predict")
async def predict(request: PredictionRequest):
    prediction = model.predict([request.features])
    return {"prediction": prediction[0]}

A/B Testing

Validate new models in production:

  • Shadow mode: new model runs alongside old, results compared
  • Canary deployment: gradual rollout to small percentage of traffic
  • Blue-green deployment: instant switch with quick rollback capability

Security Best Practices

  • Never commit credentials or API keys
  • Use secrets management (AWS Secrets Manager, HashiCorp Vault)
  • Implement authentication and authorization for model APIs
  • Sanitize and validate all inputs
  • Regular security audits of dependencies

Documentation

Maintain comprehensive documentation:

  • Model cards describing model purpose, performance, limitations
  • Data cards documenting dataset characteristics
  • API documentation for model endpoints
  • Runbooks for common operations and troubleshooting

Cost Optimization

  • Right-size compute resources
  • Use spot instances for training
  • Implement model quantization and pruning
  • Cache predictions when appropriate
  • Monitor and alert on cost anomalies

Conclusion

MLOps is not a one-time setup but an ongoing practice. Start with the basics—version control, experiment tracking, and monitoring—then gradually adopt more advanced practices as your needs grow.

Remember: the goal is reliable, maintainable ML systems that deliver value to users. Don't overcomplicate things early on, but do plan for scale from the beginning.
